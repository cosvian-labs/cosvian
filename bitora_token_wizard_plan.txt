📘 Bitora 5-Step Token Wizard (Simple Mode)
Implementation Plan (using existing `x/token` module)

🎯 Goal
Enable users to create native Bitora tokens via a simple 5-step wizard in Norix Wallet — no smart contract required. All logic is implemented via Cosmos SDK (`x/token`), enabling seamless mint, transfer, and registration.

✅ Overview
- Built on top of existing `x/token` module
- Reuses `MintToken` and `BurnToken` logic
- Adds `MsgCreateToken` to support token instantiation
- Integrated with:
  - `x/tokenregistry` (for POS/wallet compatibility)
  - `x/treasury` (optional, for fee subsidy or routing)
  - `x/token/fees.go` (flat-fee handler, no oracle needed)

🧱 New Message Type: `MsgCreateToken`

Structure:
type MsgCreateToken struct {
  Name           string
  Symbol         string
  Decimals       uint32
  InitialSupply  sdk.Int
  MaxSupply      sdk.Int
  Mintable       bool
  POSCompatible  bool
  Creator        sdk.AccAddress
  IconURI        string // Optional
  Description    string // Optional
}

Handler Logic:
func (k Keeper) HandleMsgCreateToken(ctx sdk.Context, msg MsgCreateToken) error {
  // 1. Validate name + symbol uniqueness
  // 2. Charge flat fee via x/token/fees.go
  // 3. Store TokenMetadata in KVStore
  // 4. Call k.MintToken(ctx, msg.Creator, tokenID, initialSupply)
  // 5. If POSCompatible, register tokenID in x/tokenregistry
  // 6. Emit EventTokenCreated
}

🗂️ Token Metadata Structure
type TokenMetadata struct {
  Name            string
  Symbol          string
  Decimals        uint32
  MaxSupply       sdk.Int
  CurrentSupply   sdk.Int
  Mintable        bool
  Creator         sdk.AccAddress
  POSCompatible   bool
  IconURI         string
  Description     string
  CreatedAt       time.Time
}
Stored at: storeKey: TokenMetadataPrefix + TokenID

🧩 Integration Points
Module              Purpose
------------------  --------------------------------------------
x/tokenregistry     Auto-register compatible tokens for POS/Wallet
x/token/fees.go     Handle flat creation fee (e.g. 3 BTO), no oracle
x/treasury          Optional fee routing or subsidy
x/dao (optional)    DAO can later verify tokens via governance

🔄 Reused Logic
Action    Call
--------  -------------------------------------
Minting   k.MintToken(ctx, address, tokenID, amount)
Burning   k.BurnToken(ctx, address, tokenID, amount)
Transfer  Built-in transfer logic from x/token

📲 Wizard Frontend Flow
1. Token Identity        - Name, Symbol, Decimals
2. Supply Setup          - Initial amount, Max cap, Mintable toggle
3. Ownership             - Wallet address is owner
4. POS Compatibility     - Toggle for POS, Optional icon + description (IPFS)
5. Confirm & Launch      - Sign MsgCreateToken → token live in wallet

📜 Events Emitted
EventTokenCreated {
  token_id
  creator
  symbol
  supply
}

🔐 Security Constraints
- Limit max number of tokens per address (optional anti-spam)
- Verify name/symbol uniqueness chain-wide
- Metadata immutability after creation (except optional update window)
- Only registered Norix Wallets can access wizard (via authz module or internal flag)
